# Release

Signed builds are produced by the [Build and Publish](../.github/workflows/build-and-publish.yaml)
workflow: `eas build --local` on GitHub Actions runners, then `eas submit` to TestFlight and the
Play **internal** track. Nothing is published to a production store listing.

> **Nothing here has been run yet.** The pipeline is committed but has never executed — the
> placeholders and store records in [One-time setup](#one-time-setup) below are still outstanding.

The workflow is `workflow_dispatch` only — releases are always deliberate.

```
Actions → Build and Publish → Run workflow
  buildTarget: stores | android | ios     (default: stores)
  pushTag:     true | false               (default: true)
```

Outputs per run:

| | |
|---|---|
| `android-app-release.aab` | Actions artifact, plus a Play `internal` release (`releaseStatus: completed`) |
| `ios-app-release.ipa` | Actions artifact, plus a TestFlight build |
| `build-YYYY.MM.DD-<run_number>` | git tag on `origin`, when `pushTag` is true |

## How it fits together

- **`eas.json`** — one `production` build profile with `credentialsSource: "local"`, so EAS reads
  signing material from `credentials.json` in the repo instead of from EAS servers. Android builds an
  app bundle for `armeabi-v7a,arm64-v8a` only.
- **`app.config.js`** — overlays `app.json`, sourcing `slug` from `EAS_PROJECT_SLUG` and
  `extra.eas.projectId` from `EAS_PROJECT_ID`. Required at *build* time, not just submit time,
  because `appVersionSource: "remote"` + `autoIncrement: true` means `eas build` calls the EAS API to
  bump the build number / `versionCode`.
- **`modules/build/withCiBuildHardening.js`** — config plugin that disables Android Lint for release
  builds and raises the Gradle daemon heap. `android/` is gitignored and regenerated by prebuild on
  every run, so this cannot be a committed Gradle edit.
- **`.github/actions/write-dotenv`** — writes the `EXPO_PUBLIC_*` values to `.env` before the build.
  `babel-preset-expo` inlines them at bundle time, so they must be on disk, not just in the process
  environment.
- Build numbers come from the EAS remote counter. The **marketing version** (`version` in
  `app.json`) is a manual edit — bump it in a PR when you want a new user-visible version.

`eas build --local` runs `expo prebuild` **without** `--clean`, which is why the credential files can
be written into `ios/` and `android/` before the build starts. Do not add `--clean`; it would delete
them.

## Secrets

All secrets live in the **`staging`** GitHub Environment (both build jobs declare
`environment: staging`).

### Identity and signing

| Secret | Format | Notes |
|---|---|---|
| `EXPO_TOKEN` | plain | Expo access token. Needed on the **build** step too, not just submit — the remote version counter is a server call. |
| `EAS_PROJECT_ID` | plain | UUID from the EAS project. |
| `EAS_PROJECT_SLUG` | plain | Must match the project slug on expo.dev. |
| `CREDENTIALS_JSON` | **base64** | The `credentials.json` below, base64-encoded. |
| `GOOGLE_PLAY_KEYSTORE` | **base64** | Release JKS keystore. Decoded to `android/keystores/release.keystore`. |
| `GOOGLE_SERVICE_ACCOUNT_KEY_JSON` | **raw JSON** | Play Developer API service account. The one credential that is *not* base64. |
| `APPLE_PROVISIONING_PROFILE` | **base64** | App Store distribution profile. Decoded to `ios/certs/profile.mobileprovision`. |
| `APPLE_DISTRIBUTION_CERTIFICATE` | **base64** | Distribution `.p12`. Decoded to `ios/certs/dist-cert.p12`. |
| `APPLE_APIKEY` | **base64** | App Store Connect API key `.p8`. |
| `APPLE_API_KEY_ID` | plain | ASC API key ID. |
| `APPLE_API_ISSUER_ID` | plain | ASC API issuer ID. |
| `APPLE_TEAM_ID` | plain | Apple Developer team ID. |

`credentials.json` is never committed — it exists only as `CREDENTIALS_JSON`. Its shape, with the
paths the workflow actually writes:

```json
{
  "android": {
    "keystore": {
      "keystorePath": "android/keystores/release.keystore",
      "keystorePassword": "…",
      "keyAlias": "…",
      "keyPassword": "…"
    }
  },
  "ios": {
    "provisioningProfilePath": "ios/certs/profile.mobileprovision",
    "distributionCertificate": {
      "path": "ios/certs/dist-cert.p12",
      "password": "…"
    }
  }
}
```

Encode a file for a secret with `base64 -i <file> | pbcopy` (macOS).

### App configuration

Twenty-two build-time values, one secret each, documented in [`.env.example`](../.env.example):

```
IOS_BUNDLE_IDENTIFIER                       EXPO_PUBLIC_EVM_ARBITRUM_PROVIDER
ANDROID_PACKAGE_NAME                        EXPO_PUBLIC_EVM_ARBITRUM_BUNDLER_URL
EXPO_PUBLIC_BTC_PROVIDER                    EXPO_PUBLIC_EVM_ARBITRUM_PAYMASTER_URL
EXPO_PUBLIC_BTC_NETWORK_LABEL               EXPO_PUBLIC_EVM_POLYGON_PROVIDER
EXPO_PUBLIC_EVM_ETHEREUM_PROVIDER           EXPO_PUBLIC_EVM_POLYGON_BUNDLER_URL
EXPO_PUBLIC_EVM_ETHEREUM_BUNDLER_URL        EXPO_PUBLIC_EVM_POLYGON_PAYMASTER_URL
EXPO_PUBLIC_EVM_ETHEREUM_PAYMASTER_URL      EXPO_PUBLIC_CLOUDKIT_CONTAINER_ID
EXPO_PUBLIC_EVM_ETHEREUM_NETWORK_LABEL      EXPO_PUBLIC_CLOUDKIT_API_TOKEN
EXPO_PUBLIC_EVM_DELEGATION_ADDRESS          EXPO_PUBLIC_CLOUDKIT_CALLBACK_URL
EXPO_PUBLIC_COINGECKO_API_KEY               EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID
EXPO_PUBLIC_WDK_INDEXER_API_KEY             EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID
```

Two of these — `IOS_BUNDLE_IDENTIFIER` and `ANDROID_PACKAGE_NAME` — are a different case from the
other twenty: not inlined into the JS bundle by babel at all, since no runtime code reads them. They're
read directly by `app.config.js` at prebuild time (see that file's own comments), but still need to
be a real secret here for the same underlying reason as everything else on this list: `write-dotenv`
has to put them on disk before `eas build --local` runs prebuild in a copy of the project, where
nothing outside that file is guaranteed visible. Deliberately without the `EXPO_PUBLIC_` prefix,
matching `.env.example`'s own convention for build-time-only identity values.

Any that are unset are logged as a warning and omitted from `.env`, rather than inlined as an empty
string. `IOS_BUNDLE_IDENTIFIER` and `ANDROID_PACKAGE_NAME` being unset is a valid, expected state, not
necessarily a missing secret — `app.config.js` falls back to this repo's own default identifiers when
either is blank, same as running locally with nothing set (only relevant if you actually want your own
build identity rather than this repo's own — see the README's "Making it your own" section). Two more
are **intentionally blank** in some configurations: `EXPO_PUBLIC_BTC_NETWORK_LABEL` and
`EXPO_PUBLIC_EVM_ETHEREUM_NETWORK_LABEL` should be empty whenever that network's provider points at
real mainnet (see `ENVIRONMENT.md`), so a warning for either is not necessarily a missing secret
either. Adding a new variable means editing two places: the job-level `env:` blocks in the workflow
(job-level, not step-level — a composite action's inner steps don't reliably see step `env`) and the
`put` list in `.github/actions/write-dotenv/action.yaml`.

Values are written single-quoted with `$` backslash-escaped. Both are required: Expo parses `.env`
with `node:util.parseEnv` and then runs dotenv-expand-style interpolation, so an unquoted `#` or an
unescaped `$word` **silently truncates** the value. A secret containing a literal single quote or a
newline cannot be encoded and fails the step loudly.

## One-time setup

Not yet done — the workflow will not go green until these are complete.

1. **Fill in the placeholders.**
   - `app.config.js` → `EAS_PROJECT_ID` fallback (currently `REPLACE_WITH_EAS_PROJECT_ID`).
   - `eas.json` → `submit.production.ios`: `ascAppId`, `ascApiKeyId`, `ascApiKeyIssuerId`,
     `appleTeamId`.
   - If you're shipping this under your own identity rather than this repo's own — set the
     `IOS_BUNDLE_IDENTIFIER` / `ANDROID_PACKAGE_NAME` secrets now, before item 2 below. Leaving
     both unset builds this repo's own default identifiers
     (`io.tether.wdk.starter.react.native`), which is correct if you're just testing the pipeline
     itself and not actually shipping a rebrand.
2. **Create the store records.** App id is `io.tether.wdk.starter.react.native` on both platforms
   unless you set the two secrets above to something else. Store identifiers are immutable once
   created, so do this after the rename, not before.
   - App Store Connect app → gives you `ascAppId`.
   - Play Console app, **plus one manual AAB upload**. The Play Developer API rejects the first
     upload for a track, so `eas submit` cannot bootstrap a brand-new app.
3. **Provisioning profile must include iCloud.** `app.json` declares
   `com.apple.developer.icloud-services: [CloudKit]`, and `app.config.js` sets the container
   identifier from `EXPO_PUBLIC_CLOUDKIT_CONTAINER_ID` (default `iCloud.io.tether.wdkshowcase` —
   deliberately different from the bundle id, which Apple allows). The App Store distribution
   profile must carry the iCloud entitlement with **that exact container**, or signing fails.
4. **Register the release keystore SHA-1 with Google.** After wiring the keystore, run
   `cd android && ./gradlew signingReport` and add the release SHA-1 to the Google Cloud Console
   OAuth client, against your actual package name (`ANDROID_PACKAGE_NAME` if set, otherwise
   `io.tether.wdk.starter.react.native`). Without it Google Sign-In fails with
   `DEVELOPER_ERROR (10)` in release builds only — debug builds keep working. See
   [CLOUD_BACKUP.md](CLOUD_BACKUP.md).
5. **Confirm runner access.** The Android job targets the self-hosted `app-build-linux-x64` label and
   iOS targets `macos-26-xlarge`. This repository is public, so confirm with whoever owns the runner
   that pointing it at a public repo is acceptable, and that large macOS minutes are budgeted.
   Swapping to `ubuntu-latest` / `macos-latest` is a two-line change if not.

## Verifying a release

1. `buildTarget: android`, `pushTag: false`. Check the log for `> Task :app:bundleRelease` and that
   the `versionCode` came from the EAS counter, not the template's `1`. If `IOS_BUNDLE_IDENTIFIER`/
   `ANDROID_PACKAGE_NAME` are set to something other than this repo's own default, this is also the
   point to confirm prebuild actually picked them up — the log's own `applicationId` line for the
   Gradle build should show your value, not the default. This isn't verified by the bundle-inlining
   script further below, since these two are never inlined into the JS bundle at all — they only
   ever affect the native project prebuild generates, so a build log check is the right verification
   for these specifically, not a bundle grep.
2. `buildTarget: ios`, `pushTag: false`. Watch for signing errors naming the iCloud container —
   that is item 3 above. If you set `IOS_BUNDLE_IDENTIFIER`, the signing step should reference that
   identifier too — a mismatch here usually means the provisioning profile wasn't reissued for the
   new bundle ID yet.
3. Install the TestFlight build and smoke-test the paths that prove the env made it into the bundle:
   wallet creation, the **Activity** tab (`EXPO_PUBLIC_WDK_INDEXER_API_KEY`), an EVM balance load,
   Google Sign-In and iCloud backup.
4. `buildTarget: stores`, `pushTag: true` for the real release.

### Verify env values actually reach the bundle

`babel-preset-expo` inlines a `process.env` read only when the **key is statically known**. Dot vs.
bracket notation is irrelevant (`process.env['EXPO_PUBLIC_CLOUDKIT_CONTAINER_ID']` is fine) — but an
**interpolated** key cannot be inlined and silently yields `undefined` in a release build.

This already caused a real bug: [`src/wdk/config.ts`](../src/wdk/config.ts) built its keys as
`` process.env[`EXPO_PUBLIC_EVM_${prefix}_PROVIDER`] ``, so all nine
`EXPO_PUBLIC_EVM_{ETHEREUM,ARBITRUM,POLYGON}_{PROVIDER,BUNDLER_URL,PAYMASTER_URL}` values were absent
from production bundles and Ethereum, Arbitrum and Polygon shipped with `provider: ''` — no balances,
no sends. Development hid it entirely, because the dev server supplies `EXPO_PUBLIC_*` at runtime.
Fixed by reading each variable by its literal name; there's a comment on `buildEvmConfig()` warning
against refactoring the call sites back into a loop.

Re-run this after any change to `.env` or `config.ts` — it needs no credentials and takes ~3 minutes:

```bash
npx expo export --platform android --output-dir /tmp/export-test --clear
B=$(ls /tmp/export-test/_expo/static/js/android/*.hbc); strings "$B" > /tmp/bundle.txt
while IFS= read -r l; do case "$l" in EXPO_PUBLIC_*) ;; *) continue;; esac
  k=${l%%=*}; v=$(printf '%s' "${l#*=}" | sed "s/^['\"]//;s/['\"]\$//"); [ -z "$v" ] && continue
  grep -qF -- "$v" /tmp/bundle.txt && echo "  $k inlined" || echo "  $k NOT INLINED"
done < .env
```

Every variable your code actually reads should report `inlined`. A `NOT INLINED` result for a key
nothing reads is expected noise. This also proves the worklet bundle resolved — `expo export` fails
outright without `.wdk-bundle/wdk-worklet.bundle.js`.

## Troubleshooting

**`eas build` fails immediately with an unknown `--output` flag.** The workflow passes
`--output <path>` so the artifact location is deterministic. If the pinned `eas-cli` predates that
flag, either bump `eas-cli-version` in
[`.github/actions/setup-eas`](../.github/actions/setup-eas/action.yaml) or drop the flag and locate
the artifact with `find . -maxdepth 1 -name 'build-*.aab'` — search the repo root only, since
`android/app/build/outputs/` also contains an `app-release.aab`.

**`OutOfMemoryError: Metaspace` during `lintVitalRelease`.** The hardening plugin should prevent
this; check it is still registered in `app.json` `plugins` and that
`grep -A3 'lint {' android/app/build.gradle` shows `checkReleaseBuilds false` after prebuild.

**Missing `expo` or another package after install.** npm 10 silently drops packages from
git-dependency trees. The workflow forces npm 11 — see [ENVIRONMENT.md](ENVIRONMENT.md).

**Working tree dirty after `npm ci`.** Expected. `postinstall` regenerates
`.wdk-bundle/wdk-worklet.bundle.js`, which is tracked in git despite being listed in `.gitignore`.
No CI step gates on a clean tree.
